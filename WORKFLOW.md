# Как мы вносим правки и как всё синхронизируется

Коротко: **правки просит Сергей, делает Claude, проверяет и мержит Никита.** Figma, код и история версий обновляются в одном заходе. Вручную синхронизировать ничего не нужно.

## Где что лежит

| Место | Что там | Для кого |
|---|---|---|
| **Figma** «MAVPY — Site v2 Workshop» | Страницы `EN/UA — Desktop/Mobile`: **текущий дизайн**. Вкладки `🗂 vX.Y`: замороженные копии прошлых версий | Посмотреть, как выглядит. Взять размеры в Dev Mode |
| **GitHub** `mavpy/mavpy-design`, ветка `main` | Готовый код сайта (EN `/`, UA `/ua/`) | Никита: деплой и разработка |
| **CHANGELOG.md** | Список изменений по версиям, главный текст | Все |
| **GitHub → Releases** | Тот же текст по версиям, как лента новостей | Все: «что поменялось» |

Правило: **`main` в GitHub = текущие страницы в Figma.** Если они расходятся, это ошибка, её надо исправить.

## Куда складывать правки
В Figma есть страница **✏️ Правки и контент (Serhii)**. На ней:
- **карточки правок** со статусом Новое / В работе / Готово;
- **рамки для картинок** с подписанными именами файлов и размерами;
- **поля для текстов и ссылок**;
- **черновики** для своих набросков.

Когда там что-то добавлено, напиши Claude «забери правки из Figma».

## Как внести правку: 5 шагов

1. **Сергей пишет Claude, что поменять.** Подойдёт любой формат: текст, скриншот или комментарий в Figma. Пример: «уменьши фото основателя, добавь 3 роли команды».
2. **Claude делает всё за один заход:**
   - меняет страницы в Figma;
   - меняет код в отдельной ветке;
   - дописывает в CHANGELOG раздел новой версии (`## v2.2 — дата`);
   - создаёт в Figma вкладку `🗂 v2.2 · дата`;
   - открывает pull request (PR) с описанием по шаблону.
3. **Сергей проверяет дизайн:** в Figma и в превью. Ссылку на превью Netlify сам добавляет в PR: проверка `netlify/mavpy-design/deploy-preview` → Details, адрес вида `deploy-preview-N--mavpy-design.netlify.app`. Если что-то не так, пишет Claude, и он правит в том же PR.
4. **Никита проверяет код и мержит PR.** PR с визуальными правками без обновлённой Figma не мержим, для этого в шаблоне PR есть отдельный пункт.
5. **Дальше всё автоматически:** GitHub сам ставит тег `v2.2` и публикует Release с текстом из CHANGELOG.

Перед своими правками в коде Никита делает `git pull origin main`, чтобы работать с последней версией.

## Номера версий

- `v2.1` → `v2.2` → `v2.3`: вторая цифра растёт с каждым смерженным PR, в котором поменялось что-то видимое.
- `v3.0`: первая цифра растёт только при смене направления дизайна.
- Правки, которые не видны на сайте (README, настройки), не меняют номер.

## Как посмотреть или откатить старую версию

- **Посмотреть:** в Figma открыть вкладку `🗂 vX.Y`. На GitHub открыть Releases → нужная версия.
- **Откатить код:** `git checkout vX.Y`, либо попросить Claude вернуть конкретный блок из этой версии через новый PR.

## Если Никита правит код сам

Можно, но через PR. В описании PR отметить «Figma не обновлена» и попросить Claude её догнать. Без этого Figma начнёт отставать.

## Если что-то сломалось

- **Тег или Release не появился после мержа.** В репо: Settings → Actions → General → Workflow permissions → **Read and write**, затем перезапустить Action `Release from CHANGELOG` (вкладка Actions → Run workflow).
- **Figma и сайт выглядят по-разному.** Написать Claude: «сверь Figma с main», он догонит отстающую сторону.
