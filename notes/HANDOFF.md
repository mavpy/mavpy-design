## 3. Как мы работаем (процесс одной версии)

1. Сергей кладёт правки на страницу Figma **«✏️ Правки и контент → vX.Y»**:
   - текстом в раздел 3.2 или 4;
   - картинками в раздел 2;
   - карточками в раздел 1.
2. Сергей пишет в чат: «есть правки / забери правки из Figma / делай следующую версию».
3. Claude **записывает правки текстом**: `notes/ДАТА-vX.Y-edits.md`, разбор по пунктам и вопросы.
4. **Figma:** новые страницы «vX.Y · EN Desktop 1920», «vX.Y · UA Desktop 1920», «vX.Y · EN Mobile 390», «vX.Y · UA Mobile 390». Они делаются из предыдущих, к прошлым страницам дописывается «(old)».
5. **Вёрстка:**
   - генератор `tools/build.py` собирает `index.html` (EN) и `ua/index.html` (UA);
   - стили `styles.css`: новый блок «vX.Y» дописывается в конец;
   - скрипты `main.js`.
6. **Проверка:** рендер Playwright на ширине 1440, 768 и 390, превью в `previews/`.
7. **Превью-ссылка** обновляется (артефакт, см. раздел 5).
8. **GitHub:**
   - ветка `vX.Y/edits` от предыдущей;
   - PR с базой на предыдущую ветку;
   - CHANGELOG с разделом `## vX.Y — дата`;
   - журнал шагов в notes.
9. **Figma, закрытие версии:**
   - архив «🗂 vX.Y · дата»: замороженные копии 4 макетов и список изменений;
   - страница правок переименовывается в «✏️ Правки vX.Y · дата (закрыто)» и больше не меняется;
   - создаётся новая «✏️ Правки и контент → vX.Y+1»;
   - запись на странице «📝 Changelog».
10. **Документ проекта** `meetings/ДАТА-vX.Y-edits` с той же записью.
11. **Никита мержит PR по порядку.** После мержа GitHub Action сам ставит тег `vX.Y` и создаёт Release.

**Нумерация версий.** `X` растёт при смене направления дизайна (так было при переходе v2 → v3). `Y` растёт при каждом смерженном PR с видимыми изменениями.

## 5. Дизайн v3.x: что сейчас на сайте

**Стиль «швейцарская мастерская»:**
- светлый фон, 12-колоночная сетка (1680 px контент на ширине 1920);
- один акцент — янтарный #FFAB01;
- нумерация разделов 01–08 моноширинным Roboto Mono;
- без наклеек, полароидов и рукописи.

- EN: BBH Hegarty (MORE и MAVPY в футере), Helvetica Neue Thin (clients, лицензия; запасной вариант Inter 100), Archivo 800 (заголовки), Roboto (текст), Roboto Mono (метки);

## 7. Технические заметки и ловушки
- **Генератор.** Тексты EN/UA лежат в словарях `E` и `U` в `tools/build.py`. Сборка: `python3 tools/build.py .` в корне репозитория.
- **Картинки из Figma** нельзя скачать напрямую из окружения Claude: сеть закрыта. Обходить ограничение через GitHub Actions тоже нельзя, это заблокировано. Способ один: Сергей экспортирует картинки (Cmd+Shift+E) и присылает в чат.
- **Figma API:**
  - разделы (Section) при `clone()` копируются **пустыми**. Копировать нужно детей по одному;
  - перед правкой текста надо загрузить его шрифт, включая BBH Hegarty;
  - при ошибке скрипт откатывается целиком.
- **Figma, полезные id:**
  - fileKey `hlVOUverBQLP4qj3I4FTub`;
  - логотип тёмный `36:12`, светлый `36:20`;
  - компонент «Правка» — набор вариантов на текущей странице правок;
  - страница Changelog — фрейм `15:3`.
- **GitHub из Claude:**
  - можно пушить ветки и открывать PR через `gh api`;
  - теги и Releases создаёт только Action после мержа.
- **Мобильные макеты в Figma** собираются скриптом из десктопных: перевод строк в колонку, отступы 20, уменьшенные шрифты, фото команды 240 px.
- **Именованные версии в истории Figma** через API сохранить нельзя. Их заменяют вкладки 🗂.
